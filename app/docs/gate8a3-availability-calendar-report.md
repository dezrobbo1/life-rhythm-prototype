## Calendar build-versus-buy and bounded source

We chose pinned `ical.js@2.2.1` (MPL-2.0, browser ESM, bundled TypeScript declarations, maintained recurrence/exception implementation) over writing an RFC 5545 iterator. The adapter validates the particular busy recurrence grammar it relies on and fails closed on unsupported forms. Supported: ordinary nonrecurring VEVENT; FREQ=DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, COUNT, UNTIL, BYDAY/BYMONTH/BYMONTHDAY where interpreted by the library; RDATE; EXDATE; single RECURRENCE-ID moved/modified/cancelled exceptions; DATE all-day events; UTC, floating time (explicit warning), and IANA TZID timed events including Sydney DST. BYSECOND/BYMINUTE/BYHOUR/BYWEEKNO/BYYEARDAY/BYSETPOS, unsupported recurrence RANGE, unknown timezone, missing recurring UID/master, malformed or excessive rules fail closed at import and read rather than silently dropping busy future events. Custom TZID not resolvable via the browser's IANA database is rejected even if a VTIMEZONE body is present; source normalization for such exports is a later extension. Expansion returns only occurrences overlapping the requested bounded read horizon, with an upper scan guard. Identity is UID plus original recurrence local identity; override and cancellation keep the logical slot and never duplicate the original. All-day dates remain source-local dates. The source file remains a **static local snapshot**; replace/re-import after calendar changes. No external write occurs.

One version-1 calendar source remains readable without rewriting it and has zero before/after minutes. New imports and spacing edits write version 2 while preserving source content and original imported timestamp on spacing edits; replacement preserves authored spacing. Calendar event location does not infer travel. Source controls appear in Setup and Plan through the same canonical import/remove/write path. A live Google/Microsoft/Apple provider is deferred until Gate 8A4 can define secure credentials and durable data: a local-only browser with no token backend cannot safely promise a managed live connection. The adapter remains provider-neutral.

Settings backup **v3** carries reviewed work-bound context and all existing profile/assignment authority; v1 and v2 backups remain checkable. Restore is still unavailable. Calendar source content stays outside settings backup. Database version remains v6; no destructive migration, reinterpretation of historical commute values, or remote sync is introduced.
