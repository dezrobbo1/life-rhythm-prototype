## Implemented boundary

- Official Clerk backend SDK verifies real session signatures/times against fixed public RSA key/ID, with exact issuer/party, optional actually-issued audience, user/session identity and authenticated role. Missing/foreign IDs, machine types, algorithms/keys and invalid sessions fail before provider reads. Only bearer sessions authorize the API; no cookie/client-ID override.
- Dedicated `life_rhythm` metadata schema contains only `trial_access`/`account_heads`, composite issuer/subject keys, nonnegative bigint revision, generation UUID and independent protocol/canonical versions. Forced RLS, own-identity SELECT and enabled-access head predicate complement explicit grants. Runtime writes and anonymous/default function grants are denied. The generated migration requires an operator-supplied issuer in the same connection and was applied only to isolated test engines.
- Same-origin Node GET accepts only bounded exact version/head parameters. It forwards each verified caller token with a publishable key through a fresh Supabase client. A single active-access/head query gives one statement snapshot and enforces provider RLS. PostgREST's one-to-one object/null shape and `revision::text` are validated against a real local Data API. Strict/sanitized 400/401/403/409/426/503/405 responses, no-store, exact origins, bounded parsing, timeout and disabled retries fail closed. Expected-head comparison is read-only; no writes/CAS/outbox are implemented.
- Required app mode is the deployment default. Missing/invalid auth configuration and failed/unreadable boundary responses block ordinary content and never mount legacy fallback. Explicit fixture mode is development/test-only. Account/session keys clear ready state synchronously, abort old requests and discard late responses. Successful C1 access says **device-only**, not synced. Legacy/signed-in profiles are preserved; no profile is serialized for an API request.
- Shared pure types define metadata response/head fences and the bounded versioned canonical **class manifest** for later adapters. The manifest reserves the contract inventory, including distinct settings sidecars and live routed coordinates. It is not a content transport/serializer or proof of C2 entity/link/migration validation; complete personal projection adapters and their consent remain C2. Dexie version 6, scheduler, portable format and recovery semantics are unchanged.
- `/app` remains React/Vite/Dexie; protected root runtime is unchanged. CI now typechecks the Node API and runs SQL/Data API isolation plus client scanning. SPA rewrite excludes `/api`; an actual local Node listener verifies JSON dispatch. Actual Vercel root/routing remains an operator acceptance row.
