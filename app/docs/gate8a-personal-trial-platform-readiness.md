## 8A1 contract and legacy records

Capture means remember the task **and permit quiet private planning**, without placing it directly in Today or demanding immediate action. `captured` remains scheduler eligible. A newly authored task supplies positive whole minutes for Minimum; omitted Normal inherits the exact Minimum action and minutes, and omitted Full inherits the exact Normal action and minutes. The persisted version objects are the scheduler truth. Ad-hoc tasks have no authored Task type classification; area and per-task preferences remain available, while Task type rules apply only where a real classification exists.

Historic 5/10/20 durations are preserved as saved values, with unknown authorship. No automatic backfill or inferred provenance is justified. The correction UI warns that older values may have been filled automatically, displays the stored minutes and requires an explicit saved correction. There is no schema-wide destructive migration. Newly changed definition writes mark an accepted plan for repair within the same storage transaction; while repair is pending, automatic placements are hidden and the user can retry. The original schedule cannot safely be offered as Undo for a definition edit, since its time assumptions are obsolete; existing Undo for other valid scheduler repairs remains.

Visible defaults on the two creation paths: `area: other` (shown in the form and changeable), `kind: adhoc`, `priority: normal`, `completionStyle: flexible`, no prep/travel/cleanup/transition time, `bestTime: anytime`, `frequency: 0`, `movable/droppable: true`. `normal` priority is the neutral ranking baseline; `medium` energy is projected but currently does not rank placements, and `unclear` start barrier is not projected. `simple` is a historical classification placeholder and must not drive ad-hoc Task type preferences. Time edges are authored only when entered. No user-authored purpose is fabricated for new one-offs. Any future scheduler use of these defaults needs its own authority review.

## 8A2 handoff

The coherent transition is: catalogue/template → configured personal rhythm → durable enablement → frequency/window requirement → scheduler placement → concrete occurrence → Today/Now Start → Minimum/Normal/Full completion or skip → template-linked behaviour history. Do not persist the current session Enable button as canonical authority before that path works.

## Trial start gate and classification

**Product blockers:** the 8A1–8A7 gaps above and 8A8's unpassed acceptance. Gate 8B Day 1 requires a documented 8A8 pass, current backup/recovery and evidence protocol, verified device/browser daily loop, and trustworthy scheduling and lifecycle facts. Trial outcomes must be measured without treating historic placeholders or ambiguous completions as user-authored evidence.

**Owner's Perth-only early testing:** single stable URL, one browser/device, explicit Life Shape capacity, non-recurring `.ics` files, local backups and manual feedback can support bounded prototype exploration before 8A8. Label that use as early testing and retain known limitations; it is not the longitudinal evidence trial.

**Future enhancements:** AI interpretation, notifications, inferred time preferences, richer feedback and a final learnt-about-me surface can wait for evidence of value. **Broader-beta requirements:** supported cross-device recovery/sync, provider coverage, operational security/privacy review, support and release processes need a separate decision beyond the owner's single-device early testing. A live provider connection or broad recurrence grammar is not automatically required for 8A1.
