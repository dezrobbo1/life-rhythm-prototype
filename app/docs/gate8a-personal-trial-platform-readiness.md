## 8A1 contract and legacy records

Capture means remember the task **and permit quiet private planning**, without placing it directly in Today or demanding immediate action. `captured` remains scheduler eligible. A newly authored task supplies positive whole minutes for Minimum; omitted Normal inherits the exact Minimum action and minutes, and omitted Full inherits the exact Normal action and minutes. The persisted version objects are the scheduler truth. Ad-hoc tasks have no authored Task type classification; area and per-task preferences remain available, while Task type rules apply only where a real classification exists.

Historic 5/10/20 durations are preserved as saved values, with unknown authorship. No automatic backfill or inferred provenance is justified. The correction UI warns that older values may have been filled automatically, displays the stored minutes and requires an explicit saved correction. There is no schema-wide destructive migration. Newly changed definition writes mark an accepted plan for repair within the same storage transaction; while repair is pending, automatic placements are hidden and the user can retry. The original schedule cannot safely be offered as Undo for a definition edit, since its time assumptions are obsolete; existing Undo for other valid scheduler repairs remains.

Visible defaults on the two creation paths: `area: other` (shown in the form and changeable), `kind: adhoc`, `priority: normal`, `completionStyle: flexible`, no prep/travel/cleanup/transition time, `bestTime: anytime`, `frequency: 0`, `movable/droppable: true`. `normal` priority is the neutral ranking baseline; `medium` energy is projected but currently does not rank placements, and `unclear` start barrier is not projected. `simple` is a historical classification placeholder and must not drive ad-hoc Task type preferences. Time edges are authored only when entered. No user-authored purpose is fabricated for new one-offs. Any future scheduler use of these defaults needs its own authority review.

## 8A2 implemented boundary

The coherent transition now works as: catalogue suggestion → user-confirmed template → durable plan and prospective recurrence revision → deterministic concrete instance → private scheduler placement → atomic Today projection → Start/Pause/Resume/Minimum Done/completion/skip → factual history linked to the exact instance. The first recurrence subset is flexible quota only: positive frequency per local day, Monday-start local week or local month; optional preferred weekdays; broad preferred time; positive max per day; IANA timezone; and explicit effective local date. The private-plan horizon opens intersecting recurrence periods for seven local dates. It never backfills before the effective date or the first observed horizon, and unmet quota never carries forward.

Pause and disable both stop new generation without deleting the stable plan, generated occurrences or history. Re-enable reuses the same plan. Prospective recurrence edits create monotonic revisions; already generated instance snapshots and identities remain unchanged. Template-only content edits do not create recurrence revisions. Generated occurrences are never Pool items. A Today projection explicitly references its instance, and lifecycle mutation updates both atomically. Generated-instance completions remain factual. Gate 8A6 admits an exact template/instance-linked positive Normal completion to template-scoped Normal-duration evidence; Full, Stop and legacy variant-unknown events remain excluded.

`Add to Today once` requires a user-confirmed saved template. It reuses the earliest live generated instance for that template whose eligibility includes Today; otherwise it creates one deterministic, template-linked manual Today task for the template/date. Repetition reuses that same object. The manual path does not create or change a plan and does not consume quota.

Deferred recurrence extensions include every-N-day/week/month, anchored fortnightly or weekday cadence, hard weekday rules, anchored day of month, travel/timezone policy, and full pack activation ownership. Quick Packs are preview-only. External calendar writes remain prohibited. The schema migration to database v6 adds separate plan, recurrence-revision and instance stores without promoting fixture/session enablement, old hints, or existing Library-created Today tasks. A separate v1 rhythm-authority export/check format includes configured templates, plans, revisions, instances, linked Today projections and instance-linked factual events; restore remains unavailable.

## Trial start gate and classification

**Product blocker:** Gate 8A8's genuine deployed desktop, keyboard and approximately 390 px narrow/mobile acceptance remains unpassed. Gate 8B Day 1 requires a documented 8A8 pass, current backup/recovery and evidence protocol, verified device/browser daily loop, and trustworthy scheduling and lifecycle facts. Trial outcomes must be measured without treating historic placeholders or ambiguous completions as user-authored evidence.

**Owner's Perth-only early testing:** single stable URL, one browser/device, reviewed usable-day capacity or explicit Life Shape capacity, supported recurring `.ics` files, local backups and manual feedback can support bounded prototype exploration before 8A8. Label that use as early testing and retain known limitations; it is not the longitudinal evidence trial.

**Future enhancements:** AI interpretation, notifications, inferred time preferences, richer feedback, anchored recurrence forms and a final learnt-about-me surface can wait for evidence of value. **Broader-beta requirements:** supported cross-device recovery/sync, provider coverage, operational security/privacy review, support and release processes need a separate decision beyond the owner's single-device early testing. A live provider connection or broad recurrence grammar is not automatically required for Perth-only early testing.
