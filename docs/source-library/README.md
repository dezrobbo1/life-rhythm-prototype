# Life Rhythm source library

This folder is for project evidence, provenance and historical design-source documentation. It is not loaded by the app runtime.

Life Rhythm remains local-first and non-clinical, but the source library is not product authority.

Use the active repository sources in this order:

1. [`../DOCUMENTATION_AUTHORITY.md`](../DOCUMENTATION_AUTHORITY.md) for the repository documentation hierarchy.
2. [`../../PRODUCT.md`](../../PRODUCT.md) for current product purpose, direction and true invariants.
3. [`../../MVP_PLAN.md`](../../MVP_PLAN.md) for the current implementation path and active MVP gate sequence.
4. [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md) for target technical architecture and transition strategy.
5. [`../RESEARCH_BASIS.md`](../RESEARCH_BASIS.md) for the current evidence translation and scientific boundaries.
6. [`../ux/Life_Rhythm_Design_Specification_v1_2_Evidence_Balanced.md`](../ux/Life_Rhythm_Design_Specification_v1_2_Evidence_Balanced.md) for historical/evidence-balanced UX traceability.
7. [`SOURCE_INDEX.md`](SOURCE_INDEX.md) for the source archive and packet map.

The former `app/docs/life-rhythm-current-design-spec.md` is retained as historical continuity only. It no longer governs product direction or the MVP roadmap.

The supplied `Life_Rhythm_All_Project_Sources_2026-07-12.zip` is provenance material containing the Design Source Pack v1.2, Packet 1-25 sources, project-source governance additions and historical visual/research references. It must not be imported by the production app.

Research material should be used to establish evidence strength, safety/scientific boundaries and worthwhile product hypotheses. It must not silently override current product direction, and uncertainty in the research must not automatically be converted into a permanent implementation prohibition.
